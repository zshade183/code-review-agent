# 评测数据 v2

`eval.json` 包含 50 条人工设计的合成 Python 样本：24 条单问题、12 条双问题、14 条无问题。
共 48 个标注问题，安全、潜在缺陷、代码坏味、性能各 12 个。

单问题覆盖 24 个场景，包括 SQL/命令注入、反序列化、XSS、边界与授权逻辑、
资源释放、异常处理、重复计算、重复查询和数据结构选择。双问题样本组合两个独立函数。
无问题样本使用安全实现，检验工具对参数化 SQL、无 shell 子进程等写法的误报。
双问题与无问题样本有意复用部分单问题场景，因此只用于同一冻结集合内的配对比较，
不能按样本随机拆成训练集和测试集。后续开发集应使用独立场景。

每条包含 `requirements`、代码注释中的相同约束、`sample_type`、`provenance`、
`fixed_code` 与全部预期问题。评测仅考虑明确约束下的实质问题及显式项目规范；
不标注缺文档、一般命名偏好等主观风格告警。无问题样本 `issues=[]`。

运行 `python data/build_eval_dataset.py` 可复现生成。写入前检查条数、ID、AST 结构唯一性、
修复代码语法、行号、类型与分类分布；`audit.json` 保存统计和内容指纹。
审计验证结构质量，不能替代独立人工标注复核或证明修复行为完全正确。

这是小规模合成受控基准，尚未经独立标注者复核。不得据此声称真实项目上的泛化效果。
旧版数据生成的 `reports/exp1` 数值已失效，重新运行实验后才能比较三组结果。
