# 连续追问

## 页面操作

启动 API 后执行 `streamlit run web/app.py`。启用侧边栏「会话与长期记忆」，
在「代码审查」完成审查，然后进入「连续追问」标签页发送问题。
页面自动管理会话 ID，展示最近 40 条消息；代码修改后会提示重新审查。
「清除对话并开始新会话」会删除后端会话并禁用追问，直到重新审查。
切换后端地址或项目会清空页面的旧报告与对话并分配新会话。
请求失败时保留已有消息并显示可复制的问题，便于重试。

## API 调用

先向 `POST /agent/review` 提交代码，并启用记忆（默认开启）：

```json
{"code":"x = 1", "project":"demo", "session_id":"chat-001", "extra_context":"重点关注安全问题"}
```

随后调用 `POST /agent/followup`，无需重复提交代码：

```json
{"project":"demo", "session_id":"chat-001", "question":"刚才的问题应该怎么修？"}
```

响应包含 `session_id` 和 `answer`。后续问题继续使用同一 project 和 session_id。
追问用于解释已有结果、讨论修复建议，不执行修改或重新审查。代码更新后需重新调用
审查接口；最新源码和审查摘要会替换会话中的当前快照。

同步审查和流式审查均保存会话。Python 调用方式为
`pipeline.review(code, session_id="chat-001")`，随后
`pipeline.follow_up("为什么？", session_id="chat-001")`。

记忆按项目和会话隔离，默认最多 128 个会话、每个会话 12 条消息，每条最多
6000 字符。追问携带最近 6 条消息（总计最多 12000 字符）、最近审查摘要
（最多 12000 字符，最多 12 个问题）及源码前 12000 字符；超长源码明确标记截断。
最新问题最多 6000 字符。审查回注的记忆限制为 16000 字符。
这是确定性的字符预算，不是精确 Token 计数或自动滚动语义摘要；很长的源码
或很早的对话可能需要用户补充。最近审查摘要独立保留，不随对话窗口淘汰。

会话仅保存在当前服务进程；重启、多 worker 或多实例不会共享。
生产环境需要共享存储和会话级并发控制；当前客户端应等待上一轮完成再发送下一轮。
`DELETE /agent/memory/session/chat-001?project=demo` 清除对话和源码快照。
未启用记忆、不存在或已清除的会话不能追问，API 返回 400。
项目名和会话 ID 是分组键，不替代身份认证；客户端应使用不可猜测的会话 ID。
